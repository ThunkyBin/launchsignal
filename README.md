# LaunchSignal

LaunchSignal is a founder-facing page review tool built around a GenLayer Intelligent Contract. A founder submits a public landing-page URL and a short public description of the offer. The contract fetches a bounded page excerpt; the leader and validators independently assess whether the offer, intended audience, call to action, and page-to-offer match are clear. The agreed rubric is stored on-chain.

The product idea is a lightweight “launch readiness” service for indie founders and small teams: free, shareable copy feedback first, with a possible paid history/export workspace later. This MVP is not a market-success predictor and does not make investment, legal, employment, or customer-eligibility decisions.

## Safety and limits

- Use only a public page URL and positioning text you are comfortable making permanent. Both are stored on-chain after a successful review; the fetched page body is not stored.
- Never submit private launch plans, customer data, credentials, or unpublished copy.
- A READY label means only that validators agreed on this narrow copy rubric for the fetched page. It does not prove product quality, demand, accessibility, legality, or future sales.
- Public-page content can be stale, incomplete, adversarial, or changed between validator fetches. The note is generated by the leader and is not part of validator agreement.
- The URL checks reject common local/private-looking forms, but cannot verify DNS resolution or the fetch service's redirect behavior. This is a testnet prototype.
- The site asks the wallet for an estimated test-network fee before a write. Verify the network and amount in your wallet before signing. The contract has no token, payment, custody, or payout methods.

## Contract flow

1. `review_page(page_url, offer_statement)` validates a public HTTPS URL and a 1–280 character offer description.
2. The leader fetches at most 7,000 characters and asks for a fixed JSON rubric. Page text is untrusted data; instructions embedded in it must be ignored.
3. Validators independently fetch and assess the same URL. Agreement requires identical evidence sufficiency and all four rubric flags.
4. The contract derives `READY`, `NEEDS_WORK`, or `UNCLEAR` from the agreed fields and stores the result under a sequential review ID.
5. Anyone can read a stored review with `get_review(id)` or the total with `get_review_count()`.

The four agreed flags are `offer_visible`, `audience_clear`, `cta_clear`, and `offer_matches`. The short `note` is a leader-authored explanation and is shown separately from the consensus fields.

## Run locally

Requirements: Python 3.12+, Node.js 20+.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
genvm-lint check contracts/launch_signal.py
python -m pytest tests
```

Run the web app:

```powershell
npm ci
npm run dev
```

For a hosted Studio deployment, use [GenLayer Studio](https://studio.genlayer.com/), select Studionet, load `contracts/launch_signal.py`, and deploy with no constructor arguments. Confirm the selected network and fee quote in Studio. Then open the web app, choose Studionet, paste the deployed address, and connect a compatible wallet to create a test review. The site can read finalized reviews without a wallet.

Current network details and fee policies change; check the [official GenLayer networks page](https://docs.genlayer.com/developers/networks) and the live estimate before signing.

## Project layout
